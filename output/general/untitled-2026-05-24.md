# CTO Executive Brief: CMS Admin Portal (R8)

## Platform Scope Decision

**Workflow:** cms-admin-portal-r8
**Decision:** APPROVED — structured content blocks architecture

### What We're Building
A modular, multi-tenant-ready CMS layer for the RLMplatform admin portal:
- 6 new Supabase tables (site_config, content_blocks, testimonials, portfolio_items, page_sections, media_library)
- Admin CRUD UI in Studio sidebar (Content, AI, Settings nav groups)
- Content accessor layer with hardcoded fallback (zero content loss, graceful migration)
- AI observatory dashboard with provenance badges (AGENTS.md §8 EXPLICIT in studio)

### Architecture Rationale
- **Structured blocks over headless CMS**: zero external dependencies, Supabase consolidation (ADR-0003), sub-$0/mo marginal cost
- **Structured blocks over page builder**: RSC-first (ADR-0002), no client-side JS for content rendering
- **Org-scoped isolation**: every table has org_id FK + RLS deny-by-default, multi-tenant ready from day one (ADR-0007)
- **Fallback pattern**: marketing surface looks identical until admin creates overrides — zero-risk deployment

### Security Posture
- RLS deny-by-default on all 6 tables
- Admin routes auth-gated via requireStudioSession() (AAL2/MFA enforced)
- Content accessors fail-closed to fallback on any error
- Media upload Phase 8 seam for EXIF strip + Supabase Storage
- Rich text XSS sanitization required before render (Phase 8: DOMPurify)

### Risk Assessment
- **LOW**: Schema is additive (no existing table modifications)
- **LOW**: Fallback pattern means marketing surface can't break
- **MEDIUM**: Rich text XSS surface — mitigated by Phase 8 DOMPurify gate
- **LOW**: Multi-tenant RLS tested by existing audit patterns (R3-tail, R6)

### Financial Impact
- Zero additional SaaS cost (Supabase tables are included in existing plan)
- Eliminates developer deployment cycles for content changes (~2hr/change → 0)
- Enables multi-tenant licensing (other photographers can use the platform)
